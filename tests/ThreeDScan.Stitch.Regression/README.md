# End-to-end surface stitching regression

Run from the repository root:

```powershell
dotnet run --project tests/ThreeDScan.Stitch.Regression -c Release -- --output LocalDevelop/stitch-check-new
```

The console compiles the actual pure geometry/export and request-contract sources. It does not start the API, scanner, WPF, SQL or callbacks. Existing inputs are read-only; output directories must be new. Generated analytic inputs and diagnostics are retained in the output directory.

The analytic fixtures define measured 90° roofs with known longitudinal length and independently constructed XYZ rotations. Cases cover the old scanner-Y direction, a nearly scanner-X direction, exact scanner-X, independently rotated and tilted segments, an explicit 3 mm nominal gap and a three-segment chain. Checks require the inferred axes to follow the known workpieces, at least 95% of the analytic length to remain after end trimming, consecutive retained longitudinal intervals without overlap, and a total span equal to the sum of retained segment spans and observed sampling-envelope gaps. A 1 mm longitudinal measurement raster can leave up to two raster pitches between the last/first retained measurements even when the nominal cut planes meet; no points are added to fill that gap.

The exported `StitchProcessor` PLY must reproduce every retained source measurement using its documented rigid matrix, preserve intensity, raw indices and a custom temperature attribute, and carry unique source-scan/source-point provenance. Explicit `CameraPose` is tested separately: equal zero poses must preserve overlapping samples. A negative fixture keeps both real wing planes but removes the outer 15 mm of one wing in every row; its held-out full-width quality must fail the unchanged edge/coverage checks even when its central profile matches. A single visible wing must be rejected rather than supplied with an invented second wing. Nominal joining must keep absolute calibration and physical overall-length verification false.

The incomplete-wing fixture also runs through `StitchProcessor` as the middle of three scans. Both failed seams must appear in `ValidationFailures`, including measured values, original thresholds and matching human-readable warnings, and survive serialization into the stitch report. Passing seams must leave the failure list empty. Background persistence and shared GET/callback serialization are covered separately by `tests/ThreeDScan.TaskFailure.Regression`.

Strict `ValidationPassed` remains false for the incomplete-width fixture while `AlignmentValidationPassed` is true and `BoundaryValidationPassed` is false. The API's explicitly configured point-cloud completion policy can deliver that aligned cloud with boundary warnings without changing these measurements or strict quality flags. Its exact whitelist, strict mode, alignment failures and legacy/malformed results are tested by the task-failure regression.

Eight independent boundary fixtures distinguish longitudinally clustered tail points from a complete sparse wing, including three measurements spread across the full band and different densities on the two wings. They also reject an isolated transverse density spike, retain a complete 1 mm raster, and require real 3 mm/15 mm edge losses and matching incomplete ends to fail the original edge/interior-width gates. Boundary validation counts occupied longitudinal cells relative to each wing's own typical occupancy, uses a three-column median with measured neighbours within 1.5 mm, and requires at least half-band longitudinal span. Original profile RMS/P95 and retained PLY measurements are unchanged. `UnfilteredFullSection` and `EdgeSamplingRule` record the original extreme-bin result and the supported-boundary rule alongside `FullSection`.

Ten end-location fixtures reproduce the narrower-stock failure where seven transverse columns observed only at the opposite end exceed the 2% end-coverage quantile. They cover head/tail symmetry, combined ridge-side and outer-wing fringes, a dense but spatially short patch, independent sparse/full wings, a single far-longitudinal outlier, and an analytically defined oblique end face. Short columns close to the real head/tail retain the original conservative 8/292 mm cuts exactly; they must not be discarded by a general density/span filter. A pair with independent full XYZ rotations requires the real head/tail stations, an available 25–85 mm plane-training band, unchanged measured points/attributes, disjoint fit/validation indices and the original seam-quality gates. Sparse valid end bands still need the original three samples near their endpoint; only three samples spread across the full 300 mm scan do not bypass this requirement. The before-fix binary fails the four opposite-end fringe fixtures and the full XYZ pair, while the corrected end locator passes them without lowering the 500-point fitting threshold.

Model integration checks require zero nominal gap to yield one closed solid while preserving independently placed holes in both sources. A declared 3 mm material gap must keep two closed solids and both holes. A negative fixture removes every measured sample from a longitudinal ridge corridor: matching end profiles can still pass, but the direct model remains two wing bodies and the zero-gap joined solid must be withheld while retaining the valid measured PLY. No material is inserted across that empty ridge to force a successful model.

Future stitched-model exports default to repairing exterior notches deeper than 10 mm. Integration checks compare default repair, explicit `FillOuterEdges=false`, and `ExportModels=false`: measured PLY bytes, source hashes, point counts and seam quality flags must remain identical. Actual GLB JSON metadata must carry the configured depth and distinguish applied repairs from no-op/skipped repairs; opting out restores the original model-outline behavior. Emitted GLBs also require case-sensitive `POSITION`/`NORMAL` semantics, matching float-vector accessors, valid uint triangle indices, aligned JSON/BIN chunks and accessor data within buffer boundaries. The separate solid-export runner verifies exact 9/10/11 mm threshold geometry and per-cell hole preservation.

Request-contract checks use numeric enum values as the API does: omitted mode in a new start request selects nominal butt joining, explicit `0` retains `CameraPose`, and explicit `1` selects nominal joining. The effective mode must reach the start fingerprint. Old persisted task documents and the low-level export options retain their compatible `CameraPose` default.

An optional saved-task replay reads the two extracted scanner PLY files and segment metadata, rather than reacquiring hardware or reprocessing the large original raw clouds:

```powershell
dotnet run --project tests/ThreeDScan.Stitch.Regression -c Release -- `
  --output LocalDevelop/stitch-real-new `
  --task-folder ThreeDScan.Api/bin/x64/Debug/net10.0-windows/export/tasks/SURFACE-eeea2318bc37463c986d9a603ce3b103
```

Use `--only-real` with the same task argument to run only the saved recording. Real arrangement/source provenance and held-out full-width seam quality are separate checks. The latter must pass the production RMS, P95, cross-seam 2D edge distances, coverage, held-out wing support and both ends' own interior transverse-width checks. Own interior width compares the transverse U coordinate; cross-seam checks still compare actual U/Z coordinates. An arranged cloud with a failed quality flag is a failed regression run. The summary records the actual retained intervals, gap, output point count, validation result and source integrity. This verifies the selected nominal arrangement, not the physical identity or length of the stock.
