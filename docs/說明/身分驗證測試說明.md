# ThreeDScan 身分驗證測試說明

本文件說明 **甲方 OAuth2.0 IDP + Bearer Token** 接好後如何測試。  
實作以 `libs/DAS.Authentication`（`DAS.Authentication.dll`）搭配 Api JwtBearer、WPF 授權碼登入。

---

## 1. 測試前準備

### 1.1 環境

| 項目 | 說明 |
|---|---|
| 網路 | 甲方 IDP 多半僅內網／測試區可連，**需進客戶測試區或 VPN** 才能完整測 |
| 參數 | Authority、ClientId、ClientSecret、RedirectUri、Scope、測試帳號（向甲方取得） |
| RedirectUri | 須先在 IDP 登錄；預設為 `http://127.0.0.1:5005/` |

### 1.2 啟用驗證

WPF：`ThreeDScan/appsettings.json`（或該環境覆寫檔）  
API：`ThreeDScan.Api/appsettings.json`

```json
"Authentication": {
  "Enabled": true,
  "Authority": "https://甲方IDP位址/",
  "ClientId": "（甲方提供）",
  "ClientSecret": "（甲方提供）",
  "RedirectUri": "http://127.0.0.1:5005/",
  "Scope": "openid profile email offline_access",
  "Audience": "",
  "RequireHttpsMetadata": true
}
```

說明：

- `Enabled: false`（預設）：略過登入與 JWT，本機開發用。
- `Enabled: true`：WPF 啟動需 IDP 登入；Api Controllers／Hub 需 Bearer。
- `Audience`：若 IDP 的 Access Token 有指定 audience，請填入；否則可留空。
- API 端 `ClientSecret` 非 JwtBearer 必要；WPF 換 token 時會用到。

### 1.3 啟動順序

1. 啟動 **ThreeDScan.Api**（預設 `http://localhost:5295`）
2. 啟動 **ThreeDScan** WPF

---

## 2. WPF 登入測試

| 步驟 | 操作 | 預期結果 |
|---|---|---|
| 1 | 啟動 WPF（`Authentication:Enabled=true`） | 出現「身分驗證 — 甲方 IDP」視窗 |
| 2 | 按「以 IDP 登入」 | 開啟系統瀏覽器，導向**甲方登入頁** |
| 3 | 輸入測試帳登入 | 瀏覽器顯示登入成功（可關閉） |
| 4 | 返回應用程式 | 進入主畫面；已取得 Access／Refresh Token |

常見失敗：

- 連不到 Authority → 確認是否在客戶網路／VPN  
- `redirect_uri` 不符 → 請甲方將 `http://127.0.0.1:5005/` 登錄進 Client  
- ClientId／Secret 錯誤 → 換 token 失敗

## 3. Token 驗證測試 API（規範 H(C)）

基底網址以本機為例：`http://localhost:5295`  
（若有變更，以 Api `launchSettings`／實際 port 為準。）

### 3.1 端點一覽

| 方法 | 路徑 | 說明 |
|---|---|---|
| GET | `/api/auth/validate` | Token 驗證測試；回傳 JSON（身分、claims、DLL 交叉驗證結果） |
| GET | `/api/auth/ping` | 簡單探測（啟用驗證時同樣需 Bearer） |

啟用驗證後，業務 API（如 `/api/calibration/*`）與 SignalR Hub 皆需授權。

### 3.2 Postman／瀏覽器以外工具

Header：

```http
Authorization: Bearer {access_token}
```

Access Token 來源：WPF 登入成功後由 IDP 核發。開發測試可暫時於除錯時從 `AuthSession.Current.AccessToken` 複製，或請 IDP／先前手測流程取得。

### 3.3 測試案例

| # | 操作 | 預期 |
|---|---|---|
| A | `GET /api/auth/validate` **不帶** Token | `401 Unauthorized` |
| B | `GET /api/auth/validate`，Header 帶正確 Bearer | `200`，JSON 含 `"valid": true` 與 claims |
| C | Bearer 內容亂改／截斷 | `401` |
| D | Token 已過期且未刷新 | `401` |
| E | `GET /api/auth/ping` 帶正確 Bearer | `200`，`{ "ok": true, ... }` |

### 3.4 成功回應範例（結構）

```json
{
  "valid": true,
  "authenticationEnabled": true,
  "scheme": "Bearer",
  "name": "...",
  "subject": "...",
  "claims": [ { "type": "...", "value": "..." } ],
  "dasLibrary": {
    "validated": true,
    "name": "...",
    "error": null
  }
}
```

`dasLibrary`：以 `DAS.Authentication` 的 `OpenIdConnectProvider` 再驗一次；若 Audience／簽章設定與 JwtBearer 不一致，可能出現 JwtBearer 已過關但 `dasLibrary.validated=false`，此時以 JwtBearer 結果為準，再對齊 IDP 的 audience 設定即可。

### 3.5 curl 範例

```bash
# 無 Token → 預期 401
curl -i http://localhost:5295/api/auth/validate

# 有 Token → 預期 200
curl -i http://localhost:5295/api/auth/validate ^
  -H "Authorization: Bearer 貼上_access_token"
```

## 4. 業務 API 與 SignalR

| # | 操作 | 預期 |
|---|---|---|
| 1 | 無 Token 呼叫 `POST /api/calibration/instrument` | `401` |
| 2 | 帶正確 Bearer 呼叫業務 API | 走業務邏輯（`200` 或業務錯誤，而非未授權） |
| 3 | WPF 校正監看連線 Hub（已登入） | 連線成功；Token 由 SignalR `access_token` 傳遞 |

---

## 5. Refresh Token（規範 H(B)）

| 步驟 | 操作 | 預期 |
|---|---|---|
| 1 | 登入後確認有取得 Refresh Token（Scope 建議含 `offline_access`） | 工作階段內有 refresh_token |
| 2 | Access Token 接近過期後，再觸發需授權的 API／Hub 呼叫 | 程式自動以 Refresh 換新 Access，請求仍成功 |
| 3 | Refresh 失效後再呼叫 | 失敗；需重新以 IDP 登入 |

---

## 6. 建議驗收順序（給甲方／內部）

```
1. 於客戶測試區啟動 Api + WPF（Authentication:Enabled=true）
2. WPF → 甲方登入頁 → 進入主畫面
3. 無 Token 打 /api/auth/validate → 401
4. 帶 Bearer 打 /api/auth/validate → 200 + JSON
5. 帶 Bearer 打業務 API → 成功進入業務流程
6.（可選）Access 過期後確認 Refresh 可換發並繼續呼叫
```

## 8. 本機不測 IDP 時

維持：

```json
"Authentication": {
  "Enabled": false
}
```

此時不跳登入、Api 不強制 JWT；`/api/auth/validate` 會回傳略過驗證的說明 JSON（`authenticationEnabled: false`）。  
**正式／客戶測試驗收請務必改為 `Enabled: true`。**
