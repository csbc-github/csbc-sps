# 面掃描首尾拼接

多段首尾接長使用 `POST /api/scan/surface/start` → 一次或多次 `segment` → `complete`。

新任務的 `stitchMode` 預設為 **1（NominalButtJoin）**；`nominalGapMm` 預設為 **0 mm**。每次拍攝的順序就是接續順序：第1段尾端接第2段頭端，再接第3段。角鋼的長向從兩翼平面的三維交線建立，不以掃描器 Y 取代工件長向。

```json
{
  "scannerId": "SURF-CAM-01",
  "jobId": "ANGLE-JOIN-001",
  "cameraPosition": { "x": 0, "y": 0, "z": 0, "a": 0, "c": 0 },
  "materialThicknessMm": 6,
  "stitchMode": 1,
  "nominalGapMm": 0
}
```

此例的 `materialThicknessMm: 6` 是已知材料規格，應換成現場使用的板厚。`cameraPosition` 也應填實際位置；在首尾對接模式中，第一段位置用來錨定整體，後續段的長向位置由指定的公稱間隙排列。

以 start 回傳的 `taskId` 拍下一段：

```json
{
  "taskId": "<start回傳的taskId>",
  "cameraPosition": { "x": 0, "y": 0, "z": 0, "a": 0, "c": 0 }
}
```

`segment` 沒有另設 `stitchMode`；`complete` 沿用 start 保存的模式及間隙。完成結果的 `stitchMode` 與 `nominalGapMm` 可確認實際採用的方式。監看右側會標示「依公稱間隙對接」。

對接會用各段內側板面與截面帶求剛體姿態，再用不同的近端截面驗證接縫；端部不完整的量測依全寬覆蓋裁切並記錄保留遮罩。輸出仍可透過 `raw_point_index`、`source_scan`、`source_point_index` 回查原始量測。未量得的區域不補造點，也不以幾何相似性推測掃描器實際移動距離。

翼緣驗證會排除只在局部長向區域出現的稀疏尾端分箱，避免 60 mm 內側量測帶比 10 mm 端部帶更容易收到零星外點而誤判缺寬。每翼依自己的典型長向格數核對重複觀測，並用相鄰三箱中位數抑制單箱波動；邊緣距離上限仍為 1.5 mm、共同覆蓋下限仍為 98%，RMS／P95 與兩端各自內側翼寬檢查也保留。此選擇只影響邊界驗證，不再刪除或補造輸出點。

報告的 `unfilteredFullSection` 保留未排除稀疏尾箱的結果，`fullSection` 為持續支承的翼緣比較，`edgeSamplingRule` 說明選點條件。仍未通過時，查詢與 callback 的 `error.details.validationFailures` 會列出接縫編號、檢查項目、實測值及門檻。

目前依現場選擇將 `SurfaceScan:RequireVerifiedStitchBoundaries` 設為 `false`：截面對齊通過、且只有已知翼緣檢查未通過時，點雲任務仍回 `Completed`，翼緣問題保留在 `result.warnings` 與 `result.validationFailures`。`result.alignmentValidationPassed` 為 true，`result.boundaryValidationPassed` 與嚴格總檢查 `result.validationPassed` 仍為 false；`result.boundaryVerificationRequired` 記錄當次完成條件。此狀態不代表完整翼寬已驗證。

RMS／P95、翼板支承、擬合／驗證資料互斥及未知檢查失敗仍拒絕完成。將上述設定改為 `true` 並重新啟動 API，可恢復要求翼緣也通過的完成條件。零間隙實體的連通性檢查繼續保留，點雲完成不保證一定有 STEP／GLB 附件。

完成後，監看畫面會載入拼接產物：有 GLB 時沿用模型預覽，沒有 GLB 時直接以 `stitched.ply` 顯示在「3D 點雲」。兩種產物沿用現有的區域監看指標檔；讀到 PLY 時會清除上一個 GLB，避免顯示舊結果。

公稱對接假設各段為依序接續的不同區段。即使截面檢查通過，仍不等於已獨立驗證工件物理總長；重複拍攝同一區域後選用此模式，會依設定把兩份資料排成兩段。`absoluteCoordinatesCalibrated` 不會因對接成功而變成 true。

需要依已知相機位姿保留每段實際空間位置時，明確送 `stitchMode: 0`（CameraPose）。此模式下，兩段位姿相同就會重疊。既有任務保留建立時的模式；重新呼叫 complete 不會自行切換已完成任務。
